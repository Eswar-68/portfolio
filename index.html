Layout thrash, measured in your browser

Read then write, never alternate

Batch selection was taking about a second at 100 components. The cause was ordinary: the loop read each component's geometry and wrote its style in the same pass, so every iteration forced the browser to lay out the page again.

Splitting it into one read phase and one write phase brought it to 17ms. Run it here — these are real numbers from your machine, not mine, which is why they move a little between runs.

The adjacency problem

Two neighbouring cells each own the border between them. Draw both and the heavier one is masked by the lighter; draw neither and the edge disappears at a page break. The fix was to stop inferring adjacency from column order and derive it from geometry, so arbitrary row and column spans work.

Click a cell to cycle its border weight. Shift-click to select several, then merge them into a span.
